01
The Autonomous "Whale Hunter" Pipeline
Bam\Hunter\Matching\MatchingEngine.php • server/matching.js
The Core Concept

Continuous, self-driving multi-unit asset matching that maps third-party marketplace packages (Ditch Witch, Vermeer, CAT, Deere) to qualified historical buyers across all 2,532 leads before manual intervention.

Antigravity Execution Specs
  • Hybrid Legacy + JSON Lead Scoring: Upgrade MatchingEngine::matchInventory() so it does not skip historical rows where leads.requirements JSON is null. Add an idempotent backfill migration converting legacy leads columns (type_key, brand_key, machine_make_key, machine_norm, machine, brand, type) into structured requirements JSON (category, make, model, min_year, max_hours, min_hp, budget_max) and score in 500-row keyset-paginated batches.
  • Deterministic Heavy-Equipment Spec Parser (Bam\Hunter\Parser\SpecParser): Parse raw `inventory` / `sourcing_results` rows (`title, description, specifications_text, attachments`) + `inc/oem_specs.php` (`oem_specs_for_unit()`) into `inventory.ai_specs` JSON, outputting both the flat keys required by `MatchingEngine::score()` (`year, make, model, category, hours, hp, hp_source, asking_price, pullback_lbs, thrust_lbs, torque_ft_lbs, weight_lbs`) and the structured arrays required by the 2-Page BAM Brochure (`specs, highlights, package_includes, subsystems`). Backfill OEM horsepower (`hp_source = 'oem'`) non-destructively only when `ai_specs.hp` is null.
  • Live PHP CRM Hook & Match-on-Live Gate: Hook directly into the live PHP CRM (`unit_action.php`, `add_url.php`, `api/sourcing_import.php`, `bam_app/tools/worker.php`) and trigger `MatchingEngine::matchInventory()` (`TaskType::MatchAlert` for scores > 80.0) strictly when a unit is verified and goes Live (status = 'Live' AND verified_at IS NOT NULL), never on unverified Draft saves.

The Core Concept

A rolling intent and telemetry tracker that isolates buyer engagement trends and prioritizes historical cold leads based on machine specification and brochure views, operating cleanly within Hostinger constraints.

Antigravity Execution Specs

The Safe-Staging "Shadow DB" Mirror Environment
sourcing_results • url_queue • sync_runs • ShadowStagingManager.php
The Core Concept

Total infrastructure stability isolating live asset production tables (`inventory`, `leads`) from volatile scraper ingestions, bulk uploads, and schema migrations via secure staging operations.

Antigravity Execution Specs
  • Isolated Shadow Schema Container: Implement `Bam\Hunter\Staging\ShadowStagingManager` to trap incoming marketplace sweeps (`sourcing_results`, `url_queue`, `BAM Grabber` JSON) and bulk CSV imports inside shadow staging tables (`shadow_inventory`, `shadow_leads`) before touching production.
  • Quarantine Pricing & Verification Gate: All staged/imported units default strictly to `status = 'Draft'`, `verified_at = NULL`, `public_price = NULL`, and `show_price = 0` (storing source ask only in internal `seller_cost_ask` and disabling automatic `default_markup`). Atomic promotion to live `inventory` runs only after deduplication (`url_hash`, `serial_norm`, `dedupe_key`), preview diff validation (`sync_runs.diff_json`), and automated PII leak checks pass.
